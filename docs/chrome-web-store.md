# Chrome Web Store listing

The text to enter in the Chrome Web Store developer dashboard, kept here so
that it is reviewed like code and stays in step with what the extension
does. When a change adds a permission, a kind of data, or a new place data
is sent, update this file and [PRIVACY.md](../PRIVACY.md) in the same
change. [CONTRIBUTING.md](../CONTRIBUTING.md) ("Releasing the extension")
describes the upload itself.

## Store listing tab

**Name:** holt

**Summary** (the manifest `description`, at most 132 characters):

> Screenshots, screen recordings and notes for QA, written straight into
> your repo by the local holt server.

**Category:** Developer Tools. **Language:** English.

**Description:**

> holt is for QA-ing your own app while you build it. Click through your
> app, and capture what you see from holt's toolbar menu or with a
> shortcut:
>
> • Screenshot an area, the visible part of the page, or the full page
> • Record the tab, and narrate while you do
> • Voice notes, transcribed as you speak
> • Typed notes about the page you're on
>
> Every capture lands in one notes.md file in your project, with the page
> URL and what you said or typed, next to the screenshots and recordings.
> Hand the folder to a teammate, paste it into an issue, or point your
> coding agent at it.
>
> holt needs its small local server, which writes the files. Run it in
> your project with `npx @velvet-thunder/holt`, or add the Vite plugin.
> The extension finds it on its own.
>
> Private by design: captures go only to the server on your computer.
> There are no accounts, no analytics and no tracking. Transcription uses
> Chrome's built-in speech recognition, which sends audio to Google; you
> can turn it off in Settings.
>
> Open source (MIT): https://github.com/eric435/holt

**Graphics:**

- Icon: `public/icons/icon-128.png` (96×96 artwork with 16 px of
  transparent padding, generated by `scripts/make-icons.mjs`).
- Screenshots: 1280×800 (or 640×400), PNG or JPEG, at least one and at
  most five. Not in the repository yet.
- Small promo tile: 440×280. Optional, but listings without one rank lower.
  Not in the repository yet.
- Marquee 1400×560: optional; skip it.

Suggested screenshots, in this order:

1. The toolbar menu open on the example app (`examples/vite-app`), with the
   project name in its header.
2. An area selection in progress over the example app.
3. The note window after a screenshot, with a typed note.
4. A voice note running: the transcript box in the page's corner.
5. The resulting `notes.md` in an editor, next to the `qa/` folder tree.

## Privacy practices tab

**Single purpose:**

> Capture screenshots, tab recordings and notes of the current tab for QA,
> and send them to the holt server the user runs locally, which writes
> them into the user's project.

**Permission justifications:**

| Permission | Justification |
| --- | --- |
| `activeTab` | Captures a screenshot of, records, or injects the area-selection overlay into the tab the user is on, only after the user invokes holt on that tab (shortcut or toolbar menu). No standing access to any site. |
| `scripting` | Injects holt's own bundled scripts on demand into the tab the user asked to capture: the area-selection overlay, the full-page scroll helper and the live transcript box. Nothing is injected into pages the user has not asked to capture. |
| `tabCapture` | Records the current tab's video and sound when the user clicks "Start recording", without a screen picker. Only on a tab where the user invoked holt. |
| `offscreen` | Hosts the tab and microphone recorders in the extension's own hidden page, so a recording keeps running when the menu or side panel closes and can be started from a keyboard shortcut. Grants no access to sites. |
| `sidePanel` | holt's settings panel: server, session, the list of this session's captures, and settings. |
| `storage` | Saves the user's settings on this device, and short-lived state that must survive the service worker restarting (an active recording, an unsaved note). |
| Host `http://127.0.0.1/*`, `http://localhost/*` | Sends captures to the holt server, which runs on the user's own computer, and checks pages served from localhost for a holt server (`/__holt/status`) so no setup is needed. |

**Remote code:** No, I am not using remote code. All JavaScript is in the
package; there is no `eval`, no remote scripts, and no WebAssembly from
remote sources.

**Data usage.** What to tick under "What user data do you plan to collect
from users now or in the future?" Captures only leave the device for the
user's own server, but the dashboard counts anything the extension
handles, so declare it rather than argue the point with a reviewer:

| Category | Tick | Why |
| --- | --- | --- |
| Personally identifiable information | No | |
| Health information | No | |
| Financial and payment information | No | |
| Authentication information | No | The optional holt token is a shared secret for the user's own local server, stored on the device; it is not a credential for any account. |
| Personal communications | Yes | Microphone audio for voice notes, narration and dictation (sent to Google's speech service when transcription is on). |
| Location | No | |
| Web history | Yes | The URL and title of each captured page are written into the user's notes. |
| User activity | No | No click, scroll or keystroke tracking; notes are typed on purpose by the user. |
| Website content | Yes | Screenshots and recordings of the captured tab. |

Then tick all three certifications:

- I do not sell or transfer user data to third parties, outside of the
  approved use cases.
- I do not use or transfer user data for purposes that are unrelated to my
  item's single purpose.
- I do not use or transfer user data to determine creditworthiness or for
  lending purposes.

## Before submitting

- [ ] The manifest version is higher than the published one (see
      CONTRIBUTING.md).
- [ ] The permission table above matches `manifest.json` (and
      `scripts/check-manifest.mjs`, which enforces the permission set).
- [ ] Voice notes produce a transcript in stable Chrome with a real
      microphone. The automated tests can't check this: their fake
      microphone only beeps.
- [ ] PRIVACY.md is current, and its effective date is updated if it
      changed.
- [ ] Screenshots show the current UI.
