# @holt/extension

The Chrome extension half of holt (Manifest V3). It takes screenshots, records your screen, captures voice and typed notes, and sends everything to the local holt server, which writes it into your repo. See [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md) for the big picture and [docs/SECURITY.md](../../docs/SECURITY.md) for the threat model.

## Build

From the repo root:

```sh
pnpm install
pnpm --filter @holt/extension build       # dist/ + manifest check
pnpm --filter @holt/extension dev         # rebuild on change (esbuild --watch)
pnpm --filter @holt/extension test        # unit tests (vitest, Node)
pnpm --filter @holt/extension typecheck
pnpm --filter @holt/extension smoke       # load dist/ into real Chrome and check it starts cleanly
pnpm --filter @holt/extension e2e         # real extension + real server (Vite example) in headless Chrome
```

The build is plain esbuild ([scripts/build.mjs](scripts/build.mjs)), with no extension framework. It produces:

| Source | Output | Format | Why |
| --- | --- | --- | --- |
| `src/background/index.ts` | `dist/background.js` | ESM | manifest declares `"type": "module"` |
| `src/sidepanel/index.ts` | `dist/sidepanel.js` | ESM | loaded with `<script type="module">` |
| `src/permissions/permissions.ts` | `dist/permissions.js` | ESM | microphone permission helper page |
| `src/offscreen/index.ts` | `dist/offscreen.js` | ESM | offscreen document: tab and voice recorders |
| `src/note/note.ts` | `dist/note.js` | ESM | the Alt+T quick-note popup and the note window after a screenshot |
| `src/menu/menu.ts` | `dist/menu.js` | ESM | the toolbar menu (the action's popup) |
| `src/welcome/welcome.ts` | `dist/welcome.js` | ESM | the welcome tab opened on first install |
| `src/content/*.ts` | `dist/content/*.js` | IIFE | injected with `chrome.scripting.executeScript({ files })`, which runs classic scripts only |

The icons in `public/icons` are generated by `scripts/make-icons.mjs` (no dependencies; re-run with `pnpm --filter @holt/extension icons`) and committed.

## Load it in Chrome

1. Build (see above).
2. Open `chrome://extensions`, turn on **Developer mode** (top right).
3. Click **Load unpacked** and pick `packages/extension/dist`.
4. Pin the holt icon to the toolbar (puzzle-piece menu). Clicking it opens holt's menu, and it is the recording indicator.

After rebuilding, click the reload arrow on holt's card in `chrome://extensions`. The side panel reloads with it.

**First run.** When holt is installed (from the Chrome Web Store, or loaded unpacked into a profile that never had it) it opens a **welcome tab**: what holt does, that it needs the local holt server and how to start it, a live check of the server at the fallback URL (green "Connected to <project>", or "No server found … yet"; it turns green by itself once you start one), your current shortcuts, and the transcription switch with what it sends to Google (see [Transcription](#voice-notes-transcripts-and-microphones)). It is not shown again on updates or when you reload an unpacked build. Everything on it is also in holt's menu → **Settings**.

Start the server in your project (`npx @velvet-thunder/holt`, or the Vite plugin). There is usually nothing to configure:

- **Auto-detect (the default).** On a page served from `http://localhost:<port>` or `http://127.0.0.1:<port>` (the hosts holt has host access to), holt asks that page's origin for `/__holt/status`. If holt answers (the Vite plugin), captures on that page go there. Otherwise they go to the **fallback server URL**, `http://127.0.0.1:4848` by default, which is where the standalone server listens. Other sites (and other loopback names such as `app.localhost`, `[::1]` or https, which holt has no access to) are never asked; captures there go to the fallback. Once a page's origin has answered as holt, holt never falls back for it until the browser restarts: if it stops answering (say, Vite is restarting), a capture there fails with "holt on http://localhost:5173 isn't answering" rather than landing in whatever project the fallback URL serves.
- **Always use this URL.** Under holt's menu → **Settings** → Server, pick this to send everything to one server and never probe.

Set the URL yourself when holt runs somewhere the page can't tell you: a standalone server on another port, or Vite behind another backend (Rails, Laravel, Django, ...) whose pages come from the backend's origin rather than Vite's. Then set the fallback URL to the dev server's URL (e.g. `http://localhost:5173`).

The settings panel shows a green dot, the project's name and where the server came from ("from this tab", "fixed URL", or "fallback (no holt on this page)") when it can reach it. A recording, a screenshot and its note always go to the server picked when they started, even if you navigate elsewhere meanwhile.

## Keyboard shortcuts

| Command | Default |
| --- | --- |
| Screenshot: select area | Alt+S |
| Start/stop voice note | Alt+A |
| Start/stop tab recording | Alt+R |
| Text note (popup, Enter saves) | Alt+T |
| Screenshot: visible area | not set (suggested: Alt+X) |
| Screenshot: full page | not set (suggested: Alt+W) |
| Open the settings panel | not set (holt's menu → Settings) |
| Open holt's menu ("Activate the extension") | not set (clicking the icon does it) |

Chrome allows at most four default shortcuts per extension (a fifth is a load error: "Too many shortcuts specified for 'commands': The maximum is 4."), so visible-area and full-page screenshots ship unbound. Set them (and change any other) at `chrome://extensions/shortcuts`; the panel shows a one-time tip with a link, and lists the current bindings under **Settings → Shortcuts**. Tooltips in the panel and on the toolbar icon always show the bindings Chrome actually has, not these defaults. If another extension already uses one of the defaults, or it is one of Chrome's own shortcuts on your platform, Chrome silently leaves ours unbound.

- **macOS:** Alt is Option (⌥). Chrome takes a bound ⌥+letter combination for itself, so while holt has ⌥S bound you can't type the character ⌥S normally produces (ß on a US layout) in web pages. Rebind if you need those characters.
- **Windows/Linux:** Chrome never assigns an extension's *suggested* key that is one of its own shortcuts there (Alt+D focuses the address bar, Alt+E and Alt+F open the menu), which is why recording is Alt+R rather than Alt+D. You can still pick such a key yourself at `chrome://extensions/shortcuts`; it then takes precedence over the browser's.

## The toolbar menu and the settings panel

Clicking holt's icon opens a small menu:

- **Screenshot area**, **Screenshot viewport**, **Screenshot full page**, **Voice note**, **Quick note**, **Start recording**: each does exactly what its shortcut does (the current binding is shown next to it); **Quick note** turns the menu itself into the note popup. While a voice note or recording runs, the menu offers only its **Stop** item, with the elapsed time.
- **Settings** opens the side panel, the *settings panel*: the server and session, this session's entries (one per capture: the page, the file, and your note), and the settings (server: auto-detect or a fixed URL, token, transcription, keep audio, microphone, shortcuts).

The menu's header names the project holt writes into for the page you are on. When no server answers, it says **Not connected** with the reason, and an **Open settings** button. The capture items stay usable: a capture looks for the server again, and says what went wrong if it still can't reach one. When a holt server answers but is from a release that speaks another protocol version (see [Updating](#updating-and-server-compatibility)), it says **Update needed** and which side to update.

The panel is optional; everything works with it closed:

- **Screenshots** are taken and uploaded by the service worker. Then a small **note window** opens ("Note on: <page>"): type or dictate (🎙, using the microphone picked in Settings; not shown while transcription is off) what's wrong, and press Enter or **Save**; **Skip** saves the screenshot without a note, and so does Esc while nothing is typed (with text, Esc saves it). Either way the screenshot and your note become one entry in the notes. Closing the window, or taking another screenshot while it is still open, saves the previous one with whatever you had typed, so neither the screenshot nor your words are lost; so does quitting Chrome with the window open (it is saved when Chrome starts again). Shortcuts pressed while the note window is in front act on the page you took the screenshot of, not on the note window. If the session ended while the window was open (you started a new one, or the server or dev server restarted), the screenshot can't be added to it any more: your words are saved as a separate note that names the screenshot file, and Skip just closes.
- **Tab recording (Alt+R)** and **voice notes (Alt+A)** run in an *offscreen document*, a hidden extension page the worker creates while something is recording and closes afterwards.
- **Text note (Alt+T, or the menu's Quick note)** opens a small popup under the toolbar icon with the text field focused: type, press Enter to save (Shift+Enter for a new line, Esc to close). It shows "Saved #N" and closes. If Chrome can't open the popup (for example when the browser window isn't focused), the same page opens in a small window instead.

**Status indicator.** The toolbar icon shows what is going on: a red **REC** badge while a tab recording runs, an orange **MIC** badge during a voice note, and a red dot on the icon itself. Hover it for details, e.g. "holt (acme-web): recording tab since 14:02 (⌥R to stop)". When nothing is recording, a red **!** means no holt server answers for the local page in front (neither on the page's own origin nor at the fallback URL), or the one that answers can't be used with this version of the extension; the tooltip and holt's menu say why. It is only shown on local pages (`localhost` and friends), so the icon doesn't turn red while you browse other sites. The icon is browser UI, so unlike an in-page overlay it never appears in screenshots or recordings and needs no access to the page. Pin the icon (puzzle-piece menu → pin) so it is always visible.

**Feedback.** With the panel open, results and errors appear there as messages. With it closed, the badge flashes "✓" when something was saved and "!" on an error (the error text is in the icon's tooltip for a few seconds), then goes back to REC/MIC if something is still recording.

## Recording

- **Start recording** (Alt+R, or the menu) uses `chrome.tabCapture`: no picker, records only the tab's content at the tab's size, follows the tab across navigations, and keeps going with the panel closed. While a tab is captured Chrome stops playing its sound to your speakers; holt plays it back, so you still hear the page. Closing the tab stops the recording and saves what was recorded. Chrome only allows it on a tab where you invoked holt (a shortcut, or opening holt's menu on that tab, the same rule as screenshots); `chrome://` pages and the Web Store can't be recorded.
- **Narration:** while a tab records, holt also transcribes what you say into your microphone, into the same editable box as a voice note (see below), and saves your reviewed words as the recording's note. The microphone is used for the transcript only; the video keeps just the tab's own sound. Without microphone access the recording still runs, and the box says why there is no transcript. With **Transcribe speech** off, the microphone isn't opened at all; the box is still there for typed notes. A voice note and a tab recording can't run at the same time, since both transcribe the microphone.

## Voice notes, transcripts and microphones

- **Microphone permission** belongs to the extension, not to the site you're testing. The voice recorder runs in a hidden page, where Chrome can't show a permission prompt, so the first time you record holt opens its **permissions page** in a tab (or, with the panel open, offers a "Grant microphone access" button). Allow the microphone there once; then start the voice note again.
- **Which microphone:** Settings → **Microphone**. "System default" follows your OS setting. Microphone names appear only after you have granted access (until then the list shows a "Grant access to see names" button). The list updates when you plug devices in or out. If the chosen microphone is missing when you record, holt uses the default one and tells you ("Selected microphone not found; used the default"). The microphone in use is shown in the toolbar icon's tooltip.
- **Transcripts** come from Chrome's built-in speech recognition (`webkitSpeechRecognition`), which **streams the microphone audio to Google's speech service** while it listens: during a voice note, during a tab recording (your narration), and while you dictate in the note window. holt's own uploads go only to your holt server. Recognition runs in the same hidden page as the recorder. On recent Chrome (verified with 155) it listens to the same microphone track that is being recorded; older Chrome versions ignore that and transcribe from the system default microphone, while the audio file still uses the one you picked. Offline, or if speech recognition is blocked, you still get the audio file plus a message explaining why there is no transcript.
- **Turning transcription off:** Settings → Speech → **Transcribe speech** (also on the welcome tab and the microphone permission page; on by default, saved as soon as you flip it). Off, holt never starts Chrome's speech recognition, so no audio goes to Google: voice notes still record and always keep their audio file (whatever the keep-audio setting says, since without a transcript the audio is the voice note); a tab recording doesn't use the microphone; the transcript box says "Transcription is off" and only holds what you type, which is saved as the note; and the note window has no 🎙 button. In `notes.md` such a voice note is a link to its audio (plus your typed note, if any).
- **Audio:** by default a voice note saves only your reviewed words, as its note. Turn on **Also keep the audio of voice notes** in Settings to upload the recording too. The audio is always kept when nothing was recognised, so a voice note is never empty, and always while transcription is off (the checkbox then shows checked and greyed out; your own choice comes back when you turn transcription on again).
- **Editable transcript on the page:** while a voice note or tab recording runs, a small box in the page's top-right corner shows the transcript as you speak, plus a timer, a **Stop** button and any speech-recognition error the moment it happens. Click into it to fix words or add your own while you talk; newly recognised speech is added at the end without moving your cursor (what is being recognised right now shows greyed out underneath).
- **When the recording stops:** if you never clicked into the box, it closes and the transcript is saved exactly as recognised. If you did, it stays open: finish editing, then **Save** (or Enter) or **Discard…** (asks first; discarding a tab recording deletes the video too). Nothing is saved until you choose. If you leave the page while the box is open, what is in it is saved. A review that never gets an answer is saved as recognised after an hour.
- **Getting it out of the way:** the box sits over the page without blocking it, so you can keep clicking around; drag it by its header if it covers something, or **✕** to hide it while recording (it comes back for review if you had edited it). It is hidden automatically while holt takes a screenshot of that tab, but it is part of the page, so a *tab recording* includes it. It stays in the tab you started on, survives SPA route changes, and comes back after a reload or navigation as soon as you speak again, with your edits. Pages holt can't access (chrome:// pages, the Chrome Web Store, other sites after navigating away) get no box; the transcript is then saved as recognised.

## Permissions, and why each is needed

- `activeTab`: lets holt capture, record or inject into the tab you're on, only after you invoke holt there (a shortcut, or opening holt's menu). It does not grant standing access to any site.
- `sidePanel`: the settings panel.
- `scripting`: injects the area-select overlay, the full-page scroll helper and the transcript box on demand. Nothing is injected into pages you haven't asked to capture.
- `storage`: settings, plus short-lived state that has to survive the service worker restarting (including what is recording right now).
- `offscreen`: lets the extension create its own hidden page for the recorders, so recordings survive the panel closing and can be started from shortcuts. It grants no access to sites or data.
- `tabCapture`: "Start recording" without a picker. Usable only on a tab where you invoked holt (see above).
- Host access to `http://127.0.0.1/*` and `http://localhost/*`: to talk to the holt server. A side effect is that the extension can also see the URL and title of localhost tabs, which is where your dev app usually runs.

There is no `tabs` permission and no `<all_urls>`. Updating from an earlier build adds two permissions (`offscreen`, `tabCapture`); an unpacked extension normally just gets them when you reload it.

### "Chrome only lets holt capture a tab after you invoke holt on it"

Screenshots and tab recordings need an activeTab grant for the tab. You get one by pressing a holt shortcut or opening holt's menu on that tab, so the menu's items always have it. The grant lasts until the tab navigates to a different page (SPA route changes don't count).

## Updating, and server compatibility

The extension and the server are released separately: Chrome updates a Web Store install by itself, while each project pins its own `@velvet-thunder/holt` in devDependencies. They agree on a **protocol version** (`PROTOCOL_VERSION` in `packages/shared`, reported by the server in `GET /__holt/status`; servers 0.0.2 and older don't report it and count as version 1). It only changes for breaking changes, so most extension and server releases work with each other.

When they don't match, holt treats the server like one with a problem: the toolbar icon shows the red **!**, the menu says **Update needed**, the settings panel and the welcome tab show the message, and every capture refuses up front with it (before a recording starts, before an area is dragged, when the note window opens) rather than failing after you did the work:

- *"The holt server in <project> is too old for this extension."* Update the server in that project: `npm i -D @velvet-thunder/holt@latest` (or, if you start it with npx, `npx @velvet-thunder/holt@latest`), then restart it or the Vite dev server.
- *"This holt extension is older than the holt server …"* Update the extension: `chrome://extensions` → **Developer mode** → **Update**, or wait for Chrome to do it (it checks every few hours). An unpacked build: pull, rebuild and reload it.

A new kind of capture does not change the protocol version. An older server refuses it with a message that the extension is probably newer than the server and how to update the server; holt shows that message as the capture's error.

## Known limitations

- **Tab recordings can't be tested with fake media devices:** with Chrome's `--use-fake-device-for-media-stream` flag (used by the e2e test for voice notes), tab capture fails with "Requested device not found". The e2e test therefore records tabs in a separate Chrome without that flag.
- **One recording at a time:** one tab recording or one voice note (both transcribe the microphone).
- **Full-page screenshots** scroll the page and stitch viewport captures. To keep a fixed header from repeating, the first viewport is captured as is, and fixed and `position: sticky` elements are hidden (`visibility: hidden`, so nothing shifts) for every later one, then restored. Limits of that approach:
  - sticky elements that aren't stuck yet (e.g. a sticky table header further down the page) are hidden too, so they're missing below the first viewport;
  - a pinned element's child with an explicit `visibility: visible` still repeats, and pinned elements inside shadow DOM aren't found;
  - on huge pages the scan stops after 5,000 elements, and the panel says some fixed elements may repeat;
  - a classic (non-overlay) scrollbar appears on the right edge of every band;
  - pages that scroll an inner element instead of the window (app shells with `overflow: auto` on a wrapper) come out as a single viewport;
  - capture waits up to about a second for the page width to settle (e.g. while the side panel animates open). If the window is resized mid-capture, it stops with "The page was resized during capture; try again" instead of stitching mismatched pieces;
  - capture stops at 20,000 CSS px or 40 tiles, or earlier on very wide/high-DPI screens to stay within canvas memory limits. The panel tells you when a page was cut off;
  - it takes about half a second per viewport, because Chrome limits `captureVisibleTab` to two calls per second.
- Screenshots can't be taken of `chrome://` pages, the Chrome Web Store, or other extensions' pages. Chrome doesn't allow it.
- Recorded WebM files have no duration in their header (a MediaRecorder quirk), so some players show no seek bar until the whole file has loaded.
- If holt has no access to the current tab (not localhost, and no activeTab grant yet), notes and recordings are saved with the page recorded as "Unknown page". Shortcuts always grant access, so notes and recordings started with a shortcut name their page.

## Layout

```
manifest.json            MV3 manifest (version is filled in from package.json at build time)
scripts/                 build, icons, manifest check, Chrome smoke test
public/icons/            generated PNG icons (committed)
src/
  background/            service worker: shortcuts, messages, screenshots (capture/), recorder control,
                         offscreen-document lifecycle, toolbar indicator, note popup, pending screenshots
  offscreen/             offscreen document: tab recorder, voice recorder, live transcription, uploads
  note/                  the Alt+T quick-note popup, and the note window after a screenshot (with dictation)
  menu/                  the toolbar menu (the action's popup)
  welcome/               the welcome tab opened on first install (server check, shortcuts, transcription)
  sidepanel/             the settings panel (ui/)
  content/               on-demand content scripts: area-select overlay, full-page scroll helper,
                         the editable transcript box (voice notes and tab recordings)
  permissions/           microphone permission page (opened in a tab when needed), with the transcription switch
  shared/                message bus, settings, API client, page context, storage.session state,
                         entry bodies and the protocol version check (pure, also run by the server's
                         contract test, packages/server/src/http/extension-contract.test.ts)
```

Each module starts with a comment explaining what it does and, where it matters, why it lives in that context.
