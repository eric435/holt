# @nitpick/extension

The Chrome extension half of nitpick (Manifest V3). It takes screenshots, records your screen, captures voice and typed notes, and sends everything to the local nitpick server, which writes it into your repo. See [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md) for the big picture and [docs/SECURITY.md](../../docs/SECURITY.md) for the threat model.

## Build

From the repo root:

```sh
pnpm install
pnpm --filter @nitpick/extension build       # dist/ + manifest check
pnpm --filter @nitpick/extension dev         # rebuild on change (esbuild --watch)
pnpm --filter @nitpick/extension test        # unit tests (vitest, Node)
pnpm --filter @nitpick/extension typecheck
pnpm --filter @nitpick/extension smoke       # load dist/ into real Chrome and check it starts cleanly
```

The build is plain esbuild ([scripts/build.mjs](scripts/build.mjs)), with no extension framework. It produces:

| Source | Output | Format | Why |
| --- | --- | --- | --- |
| `src/background/index.ts` | `dist/background.js` | ESM | manifest declares `"type": "module"` |
| `src/sidepanel/index.ts` | `dist/sidepanel.js` | ESM | loaded with `<script type="module">` |
| `src/permissions/permissions.ts` | `dist/permissions.js` | ESM | microphone permission helper page |
| `src/content/*.ts` | `dist/content/*.js` | IIFE | injected with `chrome.scripting.executeScript({ files })`, which runs classic scripts only |

The icons in `public/icons` are generated by `scripts/make-icons.mjs` (no dependencies; re-run with `pnpm --filter @nitpick/extension icons`) and committed.

## Load it in Chrome

1. Build (see above).
2. Open `chrome://extensions`, turn on **Developer mode** (top right).
3. Click **Load unpacked** and pick `packages/extension/dist`.
4. Pin the nitpick icon to the toolbar if you like. Clicking it opens the side panel.

After rebuilding, click the reload arrow on nitpick's card in `chrome://extensions`. The side panel reloads with it.

Start the server in your project (`npx nitpick-notes`, or the Vite plugin). The panel shows a green dot when it can reach it. The default server URL is `http://127.0.0.1:4848`. In Vite plugin mode, set it to your dev server's URL (e.g. `http://localhost:5173`) under **Settings**.

## Keyboard shortcuts

| Command | Default |
| --- | --- |
| Open the side panel | Alt+Shift+N |
| Screenshot: visible area | Alt+Shift+S |
| Screenshot: full page | Alt+Shift+F |
| Screenshot: select area | Alt+Shift+A |
| Start/stop screen recording | (unbound) |
| Start/stop voice note | (unbound) |
| Quick note (open panel, focus the note field) | (unbound) |

On macOS, Alt is Option. Chrome allows at most four default shortcuts per extension, so the other three ship unbound. To change or add shortcuts, open `chrome://extensions/shortcuts` (there is also a link under Settings in the panel). If another extension already uses one of the defaults, Chrome silently leaves ours unbound; that page shows what is actually assigned.

## Permissions, and why each is needed

- `activeTab`: lets nitpick capture or inject into the tab you're on, only after you invoke nitpick there (a shortcut or a toolbar click). It does not grant standing access to any site.
- `sidePanel`: the UI.
- `scripting`: injects the area-select overlay and the full-page scroll helper on demand. Nothing is injected into pages you haven't asked to capture.
- `storage`: settings, plus short-lived state that has to survive the service worker restarting.
- Host access to `http://127.0.0.1/*` and `http://localhost/*`: to talk to the nitpick server. A side effect is that the extension can also see the URL and title of localhost tabs, which is where your dev app usually runs.

There is no `tabs` permission and no `<all_urls>`.

### "Chrome only lets nitpick capture a tab after you invoke nitpick on it"

Screenshots need an activeTab grant for the tab. You get one by pressing a nitpick shortcut or clicking the toolbar icon on that tab. The grant lasts until the tab navigates to a different page (SPA route changes don't count). If you opened the panel earlier and then navigated, the panel's screenshot buttons fail with this message. Press a shortcut or click the icon once, then they work again.

## Recording and voice permissions

- **Screen recording** uses Chrome's screen picker (`getDisplayMedia`). Chrome only shows it right after a click, so start recording with the panel's **Record screen** button. The toggle-recording shortcut can stop a recording, but it can't start one: it opens the panel and highlights the button. You can also stop with Chrome's own "Stop sharing" bar.
- **Voice notes** use the microphone. The permission belongs to the extension, not to the site you're testing. Chrome may not show the permission prompt inside a side panel. If you get "Microphone access was blocked", click **Grant microphone access** in the message. That opens a small extension page in a normal tab where the prompt does appear. Once you allow it there, it also works in the panel.
- **Transcripts** come from Chrome's built-in speech recognition (`webkitSpeechRecognition`), which streams audio to Google's speech service. Offline, or if it's blocked, you still get the audio file, plus a message explaining why there is no transcript. Turn off **Keep audio** in Settings to upload only the transcript. Audio is always kept if there is no transcript.

## Known limitations

- **Closing the side panel stops any recording in progress, and the recording is lost.** The recorders live in the panel page (they need a document), and closing the panel destroys that page.
- **Full-page screenshots** scroll the page and stitch viewport captures. To keep a fixed header from repeating, the first viewport is captured as is, and fixed and `position: sticky` elements are hidden (`visibility: hidden`, so nothing shifts) for every later one, then restored. Limits of that approach:
  - sticky elements that aren't stuck yet (e.g. a sticky table header further down the page) are hidden too, so they're missing below the first viewport;
  - a pinned element's child with an explicit `visibility: visible` still repeats, and pinned elements inside shadow DOM aren't found;
  - on huge pages the scan stops after 5,000 elements, and the panel says some fixed elements may repeat;
  - a classic (non-overlay) scrollbar appears on the right edge of every band;
  - pages that scroll an inner element instead of the window (app shells with `overflow: auto` on a wrapper) come out as a single viewport;
  - capture waits up to about a second for the page width to settle (e.g. while the side panel animates open). If the window is resized mid-capture, it stops with "The page was resized during capture; try again" instead of stitching mismatched pieces;
  - capture stops at 20,000 CSS px or 40 tiles, or earlier on very wide/high-DPI screens to stay within canvas memory limits. The panel tells you when a page was cut off;
  - it takes about half a second per viewport, because Chrome limits `captureVisibleTab` to two calls per second.
- Screenshots can't be taken of `chrome://` pages, the Chrome Web Store, or other extensions' pages. Chrome doesn't allow it.
- Recorded WebM files have no duration in their header (a MediaRecorder quirk), so some players show no seek bar until the whole file has loaded.
- If nitpick has no access to the current tab (not localhost, and no activeTab grant yet), notes and recordings are saved with the page recorded as "Unknown page".

## Layout

```
manifest.json            MV3 manifest (version is filled in from package.json at build time)
scripts/                 build, icons, manifest check, Chrome smoke test
public/icons/            generated PNG icons (committed)
src/
  background/            service worker: shortcuts, messages, screenshots (capture/), uploads
  sidepanel/             the UI (ui/), recorders (recorder/), panel-side uploads
  content/               on-demand content scripts: area-select overlay, full-page scroll helper
  permissions/           microphone permission page (opened in a tab when needed)
  shared/                message bus, settings, API client, page context, storage.session state
```

Each module starts with a comment explaining what it does and, where it matters, why it lives in that context.
