# @holt/extension

The Chrome extension half of holt (Manifest V3). It takes screenshots, records your screen, captures voice and typed notes, and sends everything to the local holt server, which writes it into your repo. See [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md) for the big picture and [docs/SECURITY.md](../../docs/SECURITY.md) for the threat model.

## Build

From the repo root:

```sh
pnpm install
pnpm --filter @holt/extension build       # dist/ + manifest check
pnpm --filter @holt/extension dev         # rebuild on change (esbuild --watch)
pnpm --filter @holt/extension test        # unit tests (vitest, Node)
pnpm --filter @holt/extension typecheck
pnpm --filter @holt/extension smoke       # load dist/ into real Chrome and check it starts cleanly
pnpm --filter @holt/extension e2e         # real extension + real server (Vite example) in headless Chrome
```

The build is plain esbuild ([scripts/build.mjs](scripts/build.mjs)), with no extension framework. It produces:

| Source | Output | Format | Why |
| --- | --- | --- | --- |
| `src/background/index.ts` | `dist/background.js` | ESM | manifest declares `"type": "module"` |
| `src/sidepanel/index.ts` | `dist/sidepanel.js` | ESM | loaded with `<script type="module">` |
| `src/permissions/permissions.ts` | `dist/permissions.js` | ESM | microphone permission helper page |
| `src/offscreen/index.ts` | `dist/offscreen.js` | ESM | offscreen document: tab and voice recorders |
| `src/note/note.ts` | `dist/note.js` | ESM | the Alt+T quick-note popup |
| `src/content/*.ts` | `dist/content/*.js` | IIFE | injected with `chrome.scripting.executeScript({ files })`, which runs classic scripts only |

The icons in `public/icons` are generated by `scripts/make-icons.mjs` (no dependencies; re-run with `pnpm --filter @holt/extension icons`) and committed.

## Load it in Chrome

1. Build (see above).
2. Open `chrome://extensions`, turn on **Developer mode** (top right).
3. Click **Load unpacked** and pick `packages/extension/dist`.
4. Pin the holt icon to the toolbar (puzzle-piece menu). Clicking it opens the side panel, and it is the recording indicator.

After rebuilding, click the reload arrow on holt's card in `chrome://extensions`. The side panel reloads with it.

Start the server in your project (`npx holt`, or the Vite plugin). The panel shows a green dot and the project's name when it can reach it. The default server URL is `http://127.0.0.1:4848`. In Vite plugin mode, set it to your dev server's URL (e.g. `http://localhost:5173`) under **Settings**.

## Keyboard shortcuts

| Command | Default |
| --- | --- |
| Screenshot: select area | Alt+S |
| Start/stop voice note | Alt+A |
| Start/stop tab recording | Alt+R |
| Text note (popup, Enter saves) | Alt+T |
| Screenshot: visible area | not set (suggested: Alt+X) |
| Screenshot: full page | not set (suggested: Alt+W) |
| Open the side panel | not set (clicking the icon does it) |

Chrome allows at most four default shortcuts per extension (a fifth is a load error: "Too many shortcuts specified for 'commands': The maximum is 4."), so visible-area and full-page screenshots ship unbound. Set them (and change any other) at `chrome://extensions/shortcuts`; the panel shows a one-time tip with a link, and lists the current bindings under **Settings → Shortcuts**. Tooltips in the panel and on the toolbar icon always show the bindings Chrome actually has, not these defaults. If another extension already uses one of the defaults, or it is one of Chrome's own shortcuts on your platform, Chrome silently leaves ours unbound.

- **macOS:** Alt is Option (⌥). Chrome takes a bound ⌥+letter combination for itself, so while holt has ⌥S bound you can't type the character ⌥S normally produces (ß on a US layout) in web pages. Rebind if you need those characters.
- **Windows/Linux:** Chrome never assigns an extension's *suggested* key that is one of its own shortcuts there (Alt+D focuses the address bar, Alt+E and Alt+F open the menu), which is why recording is Alt+R rather than Alt+D. You can still pick such a key yourself at `chrome://extensions/shortcuts`; it then takes precedence over the browser's.

## Headless mode: the panel is optional

Every shortcut works with the side panel closed:

- **Screenshots** are taken and uploaded by the service worker, as before.
- **Tab recording (Alt+R)** and **voice notes (Alt+A)** run in an *offscreen document*, a hidden extension page the worker creates while something is recording and closes afterwards. They keep running if you close the panel, and the panel's **Record tab** / **Voice note** buttons drive the same recorders.
- **Text note (Alt+T)** opens a small popup under the toolbar icon with the text field focused: type, press Enter to save (Shift+Enter for a new line, Esc to close). It shows "Saved #N" and closes. If Chrome can't open the popup (for example when the browser window isn't focused), the same page opens in a small window instead. The panel's own note field uses the same keys.

**Status indicator.** The toolbar icon shows what is going on: a red **REC** badge while a tab (or window/screen) recording runs, an orange **MIC** badge during a voice note (REC if both), and a red dot on the icon itself. Hover it for details, e.g. "holt (acme-web): recording tab since 14:02 (⌥R to stop)". The icon is browser UI, so unlike an in-page overlay it never appears in screenshots or recordings and needs no access to the page. Pin the icon (puzzle-piece menu → pin) so it is always visible.

**Feedback.** With the panel open, results and errors appear there as messages. With it closed, the badge flashes "✓" when something was saved and "!" on an error (the error text is in the icon's tooltip for a few seconds), then goes back to REC/MIC if something is still recording.

## Recording

- **Record tab** (Alt+R, or the panel button) uses `chrome.tabCapture`: no picker, records only the tab's content at the tab's size, follows the tab across navigations, and keeps going with the panel closed. While a tab is captured Chrome stops playing its sound to your speakers; holt plays it back, so you still hear the page. Closing the tab stops the recording and saves what was recorded. Chrome only allows it on a tab where you invoked holt (a shortcut or a toolbar click on that tab, the same rule as screenshots); `chrome://` pages and the Web Store can't be recorded.
- **Record a window or screen…** (panel only) uses Chrome's screen picker (`getDisplayMedia`). Chrome only shows the picker right after a click in a visible page, so this one can't be started from a shortcut or run in the background: it stops if you close the panel. You can also stop it with Chrome's own "Stop sharing" bar.

## Voice notes and microphones

- **Microphone permission** belongs to the extension, not to the site you're testing. The voice recorder runs in a hidden page, where Chrome can't show a permission prompt, so the first time you record holt opens its **permissions page** in a tab (or, with the panel open, offers a "Grant microphone access" button). Allow the microphone there once; then start the voice note again.
- **Which microphone:** Settings → **Microphone**. "System default" follows your OS setting. Microphone names appear only after you have granted access (until then the list shows a "Grant access to see names" button). The list updates when you plug devices in or out. If the chosen microphone is missing when you record, holt uses the default one and tells you ("Selected microphone not found; used the default"). The microphone in use is shown under the Voice note button.
- **Transcripts** come from Chrome's built-in speech recognition (`webkitSpeechRecognition`), which streams audio to Google's speech service. It runs in the same hidden page as the recorder. On recent Chrome (verified with 155) it listens to the same microphone track that is being recorded; older Chrome versions ignore that and transcribe from the system default microphone, while the audio file still uses the one you picked. Offline, or if speech recognition is blocked, you still get the audio file plus a message explaining why there is no transcript. Turn off **Keep audio** in Settings to upload only the transcript. Audio is always kept if there is no transcript.

## Permissions, and why each is needed

- `activeTab`: lets holt capture, record or inject into the tab you're on, only after you invoke holt there (a shortcut or a toolbar click). It does not grant standing access to any site.
- `sidePanel`: the UI.
- `scripting`: injects the area-select overlay and the full-page scroll helper on demand. Nothing is injected into pages you haven't asked to capture.
- `storage`: settings, plus short-lived state that has to survive the service worker restarting (including what is recording right now).
- `offscreen`: lets the extension create its own hidden page for the recorders, so recordings survive the panel closing and can be started from shortcuts. It grants no access to sites or data.
- `tabCapture`: "Record tab" without a picker. Usable only on a tab where you invoked holt (see above).
- Host access to `http://127.0.0.1/*` and `http://localhost/*`: to talk to the holt server. A side effect is that the extension can also see the URL and title of localhost tabs, which is where your dev app usually runs.

There is no `tabs` permission and no `<all_urls>`. Updating from an earlier build adds two permissions (`offscreen`, `tabCapture`); an unpacked extension normally just gets them when you reload it.

### "Chrome only lets holt capture a tab after you invoke holt on it"

Screenshots and tab recordings need an activeTab grant for the tab. You get one by pressing a holt shortcut or clicking the toolbar icon on that tab. The grant lasts until the tab navigates to a different page (SPA route changes don't count). If you opened the panel earlier and then navigated, the panel's buttons fail with this message. Press a shortcut or click the icon once, then they work again.

## Known limitations

- **Closing the side panel stops a window/screen recording** ("Record a window or screen…"), and that recording is lost: it lives in the panel page. Tab recordings and voice notes are not affected.
- **Tab recordings can't be tested with fake media devices:** with Chrome's `--use-fake-device-for-media-stream` flag (used by the e2e test for voice notes), tab capture fails with "Requested device not found". The e2e test therefore records tabs in a separate Chrome without that flag.
- **Only one tab recording at a time**, and not while a window/screen recording is running.
- **Full-page screenshots** scroll the page and stitch viewport captures. To keep a fixed header from repeating, the first viewport is captured as is, and fixed and `position: sticky` elements are hidden (`visibility: hidden`, so nothing shifts) for every later one, then restored. Limits of that approach:
  - sticky elements that aren't stuck yet (e.g. a sticky table header further down the page) are hidden too, so they're missing below the first viewport;
  - a pinned element's child with an explicit `visibility: visible` still repeats, and pinned elements inside shadow DOM aren't found;
  - on huge pages the scan stops after 5,000 elements, and the panel says some fixed elements may repeat;
  - a classic (non-overlay) scrollbar appears on the right edge of every band;
  - pages that scroll an inner element instead of the window (app shells with `overflow: auto` on a wrapper) come out as a single viewport;
  - capture waits up to about a second for the page width to settle (e.g. while the side panel animates open). If the window is resized mid-capture, it stops with "The page was resized during capture; try again" instead of stitching mismatched pieces;
  - capture stops at 20,000 CSS px or 40 tiles, or earlier on very wide/high-DPI screens to stay within canvas memory limits. The panel tells you when a page was cut off;
  - it takes about half a second per viewport, because Chrome limits `captureVisibleTab` to two calls per second.
- Screenshots can't be taken of `chrome://` pages, the Chrome Web Store, or other extensions' pages. Chrome doesn't allow it.
- Recorded WebM files have no duration in their header (a MediaRecorder quirk), so some players show no seek bar until the whole file has loaded.
- If holt has no access to the current tab (not localhost, and no activeTab grant yet), notes and recordings are saved with the page recorded as "Unknown page". Shortcuts always grant access, so notes and recordings started with a shortcut name their page.

## Layout

```
manifest.json            MV3 manifest (version is filled in from package.json at build time)
scripts/                 build, icons, manifest check, Chrome smoke test
public/icons/            generated PNG icons (committed)
src/
  background/            service worker: shortcuts, messages, screenshots (capture/), recorder control,
                         offscreen-document lifecycle, toolbar indicator, note popup
  offscreen/             offscreen document: tab recorder, voice recorder (+ transcript), uploads
  note/                  the Alt+T quick-note popup
  sidepanel/             the UI (ui/), window/screen recorder (recorder/), panel-side uploads
  content/               on-demand content scripts: area-select overlay, full-page scroll helper
  permissions/           microphone permission page (opened in a tab when needed)
  shared/                message bus, settings, API client, page context, storage.session state
```

Each module starts with a comment explaining what it does and, where it matters, why it lives in that context.
